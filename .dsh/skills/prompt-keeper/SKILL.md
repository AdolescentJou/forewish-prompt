# 把 prompt 收进 forewish-prompt 库

本库 = `prompts/<分类>/<slug>.md`（每文件头部含中文概述/关键词）+ `tools/` 检索与索引工具链。
执行环境：仓库根 `/Users/oujie/Documents/dev/forewish-prompt`（所有命令在其下运行）。

## 0. 先判断：这真的是「要收藏的模板」吗

- 用户给的是**一段成形的提示词/模板**（含角色设定、指令、few-shot、JSON 模板、图像提示词等）→ 走本流程。
- 用户只是描述需求（如「帮我写个简历」）→ 不要存，改用 `python3 tools/ask.py "<需求>"` 帮 TA 找现成模板。
- 拿不准/来源很杂（如剪贴板片段）→ 按用户意图处理，至少保留原文，宁简勿臆造。

## 1. 分类（18 个分类之一）

按**内容性质**归类（与现有文件的历史错放无关）：
编程开发(代码/CLI/架构/技术角色) · 图像生成(绘图/写真/风格提示词) · 视频生成 · 文章写作(小说/诗/影评/essay) · 文案营销(带货/广告/社媒) · 效率工具(总结/PPT/邮件/工作流) · 商业职业(求职/面试/职业角色) · 数据分析(Excel/SQL/统计/金融分析) · 搜索研究(提取/研究/审阅) · 教育教学(老师/学习) · 语言学习(口语/发音) · 翻译 · 角色扮演(act as X 人设) · 音乐创作 · 游戏娱乐 · 生活健康(健身/营养/心理) · 成人内容 · 其他(兜底)

拿不准 → `其他`。

## 2. 文件名与查重

- slug = 英文标题转小写 kebab-case（去标点），冲突时加 `-2`。
- 落盘前**查重**：同分类或全库按 `slug_to_title` 相似标题检索；若找到**正文基本一致**的现有文件 → 不新建，直接提示用户「已有 xx.md，是否覆盖/跳过」，按用户答复执行。
- 来源若是 prompts.chat/Fabric 等知名仓库且库内已收录同名同内容 → 跳过并告知用户。

## 3. 写文件（严格用此模板，参考现有文件风格）

```markdown
# <英文标题（或用户给的原名）>

## 说明

用途概述：<一句话说明用途；原文为英文则保留英文原句，可为空>

中文概述：<一行 ≤45 中文字：「让 AI 扮演 X 做 Y 产出 Z / 生成… / 把…变成…」；忠于原文不臆造>
关键词：<3~6 个中英混合标签，顿号分隔，覆盖 领域/动作/对象/场景>

## 元信息（仓库提供）

- 来源仓库：用户提供 ｜ 手动收藏 ｜ <已知来源名>
- 类型：纯文本/结构化(JSON/模版)/图像/视频 按实际
- 面向开发者：是/否

## Prompt 内容

```text
<原始 prompt 一字不改完整保留；若为 JSON 模板保留 JSON>
```
```

要点：**Prompt 内容必须逐字保留原文**；中文概述/关键词是你生成的语义层；用户消息里若有占位符（`{{var}}`、`[x]`）原样保留。

## 4. 落库与索引全链路（按顺序执行）

```bash
cd /Users/oujie/Documents/dev/forewish-prompt
python3 tools/make_library.py   # 重建 tools/library.jsonl（新文件自动收录）
python3 tools/make_indexes.py   # 刷新 prompts/README.md 分类计数
python3 tools/build_index.py    # 增量向量化：只处理新增/改动文件（需 tools/.openai_key）
```

任何一步报错：贴出错误，不要绕过；`build_index.py` 走 OpenAI 兼容网关（base 在 tools/.openai_base），全量约 1-3 分钟，增量秒级。

## 5. 校验（必做，证明真的收好了）

```bash
python3 tools/ask.py "<新文件中文概述里的核心词或一句意图>" -k 3
```

- 断言：新文件能在结果里出现；该 md 内同时存在 `中文概述：` 与 `关键词：` 行；git status 只新增了本文件与 library.jsonl 等预期产物。

## 6. git 提交

```bash
git add -A && git commit -m "prompt-keeper: 新增 <分类>/<slug>（<中文概述前 20 字>）"
```

## 7. 回复用户（中文，简洁）

给：文件路径、中文概述、关键词、所属分类；若分类有争议说明备选；如果做过查重/覆盖决策，说明结果。

## 边界

- 不做：翻译/改写原文、删除或合并已存在的其它文件、向用户之外的来源外发内容。
- 批量收藏（多条 prompt）：逐条走 1→6，合并到一次 git 提交。
- 中文概述超 45 字或标签超 6 个视为不合格，需精简后再提交。
