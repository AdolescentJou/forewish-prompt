# 设计 prompt：库内优先，其次自研/联网

目标：给用户**能直接用、高质量**的 prompt。顺序永远是：

**① 本库检索 → ② 有则用/改造 → ③ 没有才自研 → ④ 必要时联网参考 → ⑤ 可选收录回库**

执行环境：仓库根 `/Users/oujie/Documents/dev/forewish-prompt`。

## 0. 先弄清需求（含糊时必须先问或做合理假设并说明）

- 目标平台：对话型 LLM（ChatGPT/Claude/豆包…）？图像生成（Midjourney/SD）？视频？结构化 JSON/工具调用？
- 任务与产出：输入什么 → 期望输出什么格式。
- 语言、语气、专业度；是否有约束（长度、风格、成本）。
- 若用户没说平台但需求含"画/图"→ 按图像类处理并提示。

## 1. 库内检索（必做，别跳过）

```bash
cd /Users/oujie/Documents/dev/forewish-prompt
python3 tools/ask.py "<用户意图，中文大白话>" -k 6          # 默认混合(关键词+向量)
python3 tools/ask.py "<换一种说法/英文表达>" -k 6 --mode semantic   # 语义路再捞一轮
```

- 取两轮 top 结果**按路径去重**。
- 对每个候选**用 read 读完整文件**核对（只看概述/标签会误判），挑最贴合的 1~3 个。

## 2. 库里有合适的 → 给现成 or 改造（优先路径）

- **直接可用**：给出 文件路径 + 中文概述 + 完整内容（代码块），告诉用户怎么用。
- **需要定制**：以库内文件为骨架做最小改造（替换示例/占位/补充你的场景细节），并注明「基于 `prompts/<分类>/<file>.md` 改造」。
- **可以组合**：多个模板各取所长拼装时，逐条说明来源与取舍。
- 改造后同样要满足第 4 步的质量标准。

## 3. 确认没有合适的 → 自研 / 联网

- **自研质量标准**（按需取舍，别堆砌）：
  1. 角色/身份（Act as…）——仅当有助稳定表现；
  2. 任务 + 明确输入与**输出格式**（结构、清单、JSON schema 均可）；
  3. 上下文与约束（受众、语气、长度、不许做的事、成本）；
  4. few-shot 示例（1~3 个，比纯描述更能定调）；
  5. 可填项用 `{{占位符}}` 表达，方便用户复用；
  6. 复杂任务给"步骤化/先拆解再回答"引导。
- 与第 0 步的平台匹配：图像类给主体/环境/构图/风格/光线/参数；代码类给语言/框架/输入输出样例；JSON 类直接给 schema。
- **联网参考**（可选但鼓励用于你不熟的领域）：用 web_search 找该领域的优秀公开 prompt 或官方 Prompt 工程指南，**在回答中给出来源链接**；参考后仍要写成贴合用户需求的版本，不要整段照搬。
- 产出后附一句**设计思路** + 用法 + 可调参数。

## 4. 自检（交付前过一遍）

- 只保留了必要指令（不啰嗦不堆砌）？占位符和示例是否齐全？输出格式是否明确？
- 是否有与目标平台能力不符的要求（如让纯文本模型"生成图片"）？
- 中文概述/可读性：用户能一眼看懂用途并直接复制使用。
- 如果改造/自研产物的确优于库内且用户明确想要留存 → 询问是否收录（走 prompt-keeper 流程），不要擅自在库里新增文件。

## 5. 回复格式（中文，清晰）

1. **结论一句话**：来源 = 库内命中/基于某文件改造/全新设计/参考了哪些链接；
2. **完整 prompt**（放代码块，可直接复制）；
3. **怎么用/怎么调**：必填占位、建议平台、常见坑。

## 边界

- 严禁假装"库里有"：必须真实运行 ask.py 并读过文件，找不到就说找不到（那才轮到自研/联网）。
- 不改动库内任何文件，除非用户明确要求收录（那属于 prompt-keeper）。
- 涉及版权/商用敏感的源（如付费模板站）只借鉴思路，不复刻原文。
